## 合意した判断原則

1. 分析の深さと実用性を優先し、自律性と効率は品質を維持する条件下で改善する。
2. 承認範囲内の調査順序・説明構成・分析の深さ・必要な検証はAIが選ぶ。
3. 承認、既存変更の保護、機密情報の保護、統計的前提、事実と推論の区別は保持する。
4. 比較条件を揃え、通常課題と難しい課題でスキルなし・現行・改善版を比較する。差が曖昧な場合だけ追加確認する。
5. 変更なし、効果未確認、統合候補、廃止候補も正当な結論とする。候補化は削除の承認ではない。
6. Teachは前回の理解状況を次の説明・演習に反映できるかを評価する。単発解説への万能化は目指さない。
7. writing-great-skillsは具体的な設計判断への寄与を評価する。翻訳や短文化のみを成果としない。
8. 個人の実務に見合う確認に留め、網羅的認証試験・新たなQA基盤の構築は行わない。
