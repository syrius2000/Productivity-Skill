## 目的と設計

入口であるcode-understanding-proが、依頼の目的・対象の複雑さ・誤判断の影響から深さと成果物を選ぶ。code-understanding-pyramidは不足する理解の枠組み、stats-sql-comprehensionは統計・SQLの専門観点を補う。最初から統合・削除しない。

Quickでは必要な文脈・挙動・不確実性を押さえて回答できれば、無関係な設計調査を省略できる。Full／Reviewでは重要な構造・副作用・前提を落とさない。図は処理数で一律要求せず、分岐・相互作用・データ変化が図で理解しやすくなる場合に使う。

SQLでは粒度・JOIN・集計の変化、統計では対象母集団・推定対象・欠測・前提・バイアスを課題に応じて選ぶ。選択しなかった重要そうな観点には理由を示す。チェックリスト全項目を機械的に回答へ展開しない。
