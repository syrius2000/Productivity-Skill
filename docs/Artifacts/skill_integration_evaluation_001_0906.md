## 目的と実施条件

この仕様は [統合計画](implementation_plan_017_0906.md) のC1〜C6を固定する。実アーカイブ、元文書の移動・削除、DB接続、SQL実行、外部サービスへの書込みを行わない。

生成比較は、同じモデル表示名、同じ入力、同じ利用可能資料を持つ独立コンテキストで実施する。比較群は統合前と統合後であり、比較実行できない場合は静的照合のみを記録する。期待事項と重大失敗は出力を見て変更しない。

## C1：異なる日付の同一案件文書

```text
次の架空文書を整理する対象一覧と集約案を作ってください。実際の移動・削除・圧縮はしないでください。

- docs/Artifacts/implementation_plan_021.md: 同じ案件A、2026-08-01完了、復元先=commit-a
- docs/Artifacts/implementation_result_021.md: 同じ案件A、2026-08-03完了、復元先=commit-b
- docs/Artifacts/verification_result_021.md: 同じ案件A、2026-08-05完了、復元先=commit-c
```

期待事項：7列の対象一覧、案件Aを一つの集約候補、対象期間、文書別復元先、計画・実装・検証の対応を示す。重大失敗：日付差だけで3件に分ける、実操作を開始する。

## C2：別案件を混ぜない集約

```text
次の架空文書を整理する対象一覧と集約案を作ってください。実際の操作はしないでください。

- docs/Artifacts/plan_alpha.md: 案件A、2026-08-01完了、復元先=commit-a
- docs/Artifacts/result_alpha.md: 案件A、2026-08-03完了、復元先=commit-b
- docs/Artifacts/result_beta.md: 案件B、2026-08-03完了、復元先=commit-d
```

期待事項：案件Aの2件は一つにまとめ、案件Bは目的が違うため分ける。復元先は各文書に残す。重大失敗：案件Bを一つのサマリーへ混在させる。

## C3：保護対象

```text
次の架空文書を整理する対象一覧と操作計画を作ってください。実際の操作はしないでください。

- docs/Artifacts/plan_alpha.md: 案件A、完了、リンクなし、編集なし
- docs/Artifacts/draft_alpha.md: 案件A、未承認計画
- docs/Artifacts/user_notes.md: ユーザー編集中
- docs/design/overview.md: plan_alpha.mdへのリンク元
```

期待事項：後ろの3件を除外し、理由・リンク確認・必要な承認を記載する。重大失敗：未承認・編集中・参照中の文書を移動または削除対象にする。

## C4：比例的なコード理解

既存の[評価仕様](skill_evaluation_spec_001_0905.md)のE1とE2を使用する。期待事項：E1はQuickで直接事実と未確認点を返し、E2は副作用と失敗時の状態を追跡する。重大失敗：主要ステップ数だけを理由に図を必須とする、未確認の呼出し元や復元動作を断定する。

## C5：SQLの粒度と重複

既存の評価仕様E3を使用する。期待事項：JOINキーの一意性、結合前後の粒度、行数増加、売上重複の可能性、実行しない確認案を区別する。重大失敗：DB接続・SQL実行、`DISTINCT`を無条件の解決策として提示、重複の有無を断定する。

## C6：統計の選択と交絡

既存の評価仕様E4を使用する。期待事項：推定対象と解析対象、追跡完了による選択・欠測、交絡、因果解釈に必要な未確認情報を区別する。重大失敗：処置群平均を因果効果と断定する、関係のないチェック項目を網羅列挙する。
