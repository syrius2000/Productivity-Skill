## 比較と判定の仕様

- 比較群は対象スキルなし、現行、改善版。対象外の共通指示・ツール権限・承認状態・入力・利用可能参照を同一にする。親子3件の比較では、どの構成をロードしたか明記する。
- 各群は新しい独立コンテキストで実行する。共通指示を外して「スキルなし」を有利または危険にしない。採点用の期待事項と他群の回答は生成側へ渡さない。
- モデル名、実施日時、利用可能ならバージョン・推論設定・実行時間・トークン、実際に読んだファイル、失敗や未実行の理由を記録する。取得できない値は未取得とする。
- 必須制約違反・重大な誤り・重要事項の見落としを先に判定し、その後に根拠、分析の深さ、実用性、不要な往復を比較する。総合点で重大欠陥を相殺しない。
- 採否は「採用候補」「現行維持」「効果未確認」「統合候補」「廃止候補」。重要な指摘には入力中の根拠を結び付ける。印象的な語り口・文量・静的テスト合格だけで採用しない。
- 通常・難問の両方で重要品質が後退せず、一方以上で具体的な利得があれば採用候補。同等なら負担が小さい案を優先。結果が逆転・競合するなら追加比較後も無理に優劣を決めない。
- AIによる採点は補助とし、採否の根拠箇所を人が短時間で確認できる比較表にする。実行条件が揃わなければ静的評価として報告し、モデル性能改善を主張しない。

## 保存契約の解決範囲

利用先のユーザー指示を優先する。Teachの `docs/learning/`・固定ファイル名・HTMLと、コード理解の `skill_out/`・`report.md`・付随JSONは、このリポジトリの生成Artifact規則との整合確認が必要である。

段階0では既存教材・既存レポートを移動しない。テスト用入力や擬似履歴はMarkdown内に置く。保存機能の実測は、承認された一時評価環境とその明示的な保存契約が確定するまで保留する。

最小案の優先順は、利用先指示を認識して出力契約を選ぶ説明の整備、既存CLIの対応可否確認、必要な場合のみCLI・検証器の変更案である。既存CLIが対応しない保存方法を指示だけで可能としない。方式・影響範囲が増える場合は該当する後続計画を更新して再承認する。上位指示の緩和、暗黙の例外、保存CLIを迂回した直接書込みを解決策にしない。
