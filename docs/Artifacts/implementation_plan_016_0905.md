## 検証方法

作業ディレクトリはリポジトリルート。以下を読み、副作用と既存依存を確認してから承認範囲内で実行する。

```bash
python3 -B -m pytest --assert=plain -p no:cacheprovider tests/test_mutating_skill_boundaries.py tests/test_skill_frontmatter.py tests/test_skill_inventory_contract.py
```

文字列契約と行動品質は分けて報告する。既存テストが変更前の文言を固定している場合は、承認・非破壊性という目的を維持して必要最小限で更新する。安全制約を弱めてテストを合わせない。

モデル評価は架空資料と台本入力で行い、実物のアーカイブやドメイン文書の書込みはしない。アーカイブ操作の実動作を試していない場合は、その点を未実施と明示する。今回の評価範囲は候補選定・提案・承認境界・質問の質である。

## してはならないこと

- 文書が多いという理由だけで実アーカイブ、削除、圧縮、移動を始めること。
- 削除対象の選定を曖昧にする、広範囲の再帰削除を導入する、復元情報を省くこと。
- 未解決の重大な判断を「AIに任せる」で黙って確定すること。
- 合意済みの内容を何度も質問する、ユーザーが調べなくてよい環境事実を質問すること。
- 質問数や回答の短さだけをgrillingの改善指標にすること。
- 軽量化のために書込み前承認・既存編集の保護・重要な用語区別を失うこと。
- 他の段階や除外4件に便乗修正する、候補の統合・廃止を無承認で実行すること。
- コミット、push、グローバル配置、別リポジトリ更新をすること。
