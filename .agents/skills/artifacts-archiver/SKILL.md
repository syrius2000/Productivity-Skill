# Artifacts Archiver (ドキュメント自動アーカイブ・整理スキル)

`./docs/Artifacts/` 内の実装計画書や報告書を整理し、過去のドキュメントを対象期間（XX日〜YY日）を明記した原則1本（最大2本）のまとめ文書へ統合して `./docs/Archives/` に退避するスキル。ユーザーが「アーカイブして」「古い書類を整理して」「全部アーカイブして」などと依頼した時に発動する。

## 概要

プロジェクト進行に伴い `./docs/Artifacts/` ディレクトリ内に増えた過去の実装計画書（`implementation_plan_*.md`）やWalkthrough（`walkthrough_*.md`）などの旧ドキュメントを、現状に合わせて精査・集約し、**対象期間を明記した原則 1 本（例外時のみ最大 2 本）のまとめ文書**として `./docs/Archives/` へ退避します。
アクティブな計画書のファイル名や番号（例: `003`）は勝手に書き換えず保持し、トレーサビリティとリンクの健全性を維持します。

---

## 適用タイミング（Triggers）

- ユーザーが「過去の計画書をアーカイブして」「Artifactsを整理して」「古い書類をまとめて」「全部アーカイブして」などと指示した場合
- 進行中のフェーズが切り替わり、古い計画書や報告書が複数貯まってきた場合

---

## ワークフローと手順（Workflow Steps）

### 1. 読み取り調査と対象一覧 (Inventory)

まず読み取り専用で `./docs/Artifacts/` と `./docs/Archives/` を調べ、対象候補を一覧にする。一覧には各ファイルのパス、用途、完了根拠、サイズまたはハッシュ、リンク修復の有無を記載する。

- **通常指示（「整理して」「アーカイブして」等）**では、完了根拠を確認できる過去計画・報告書だけを候補にする。進行中、完了不明、または他文書から参照中のファイルは候補から除外する。
- **全件指示（「全部アーカイブして」等）**でも、対象一覧を省略しない。「全消去整理」という語だけでは削除を開始しない。
- `./docs/Artifacts/` に残るアクティブな計画書の番号は、リセットや再採番を行わず維持する。

完了条件：候補と除外理由が、ユーザーが確認できるファイル一覧になっている。

### 2. 変更計画と明示承認 (Approval)

対象一覧を基に、作成するまとめ文書、移動または削除する元ファイル、修復するリンク、復元方法を提示する。ファイルの作成、移動、削除、リンク書換えは、対象一覧を含む計画に対するユーザーの明示承認を得るまで実行しない。

完了条件：承認済みの対象一覧と変更範囲が固定されている。

### 3. 集約と検証 (Consolidation)

承認後にだけ、対象文書を精査し、**原則1本（例外時のみ最大2本）のまとめ文書**を `./docs/Archives/` に作成する。まとめ文書には対象期間、対象ファイル、主要な成果、未解決事項を記載する。

元ファイルを削除または移動する前に、まとめ文書とMarkdown相対リンクを検証する。Git管理下では削除前後の `git diff --name-status` を確認し、想定外のファイルを変更しない。

完了条件：まとめ文書、リンク検証結果、変更対象が承認済み一覧と一致する。

### 4. 反映と復元情報 (Finalize)

検証が成功した後にだけ、承認済みの元ファイルを移動または削除する。削除したパス、復元元（Gitコミットまたは退避先）、未変更のアクティブ文書を報告する。復元不能な削除や、広いパスを対象にした再帰削除は行わない。

完了条件：反映後のファイル一覧と復元情報を報告できる。

## チェックリスト

- [ ] アーカイブ対象の選定はユーザー指示（通常 vs 全件）に合致しているか？
- [ ] アクティブな計画書のファイル名・連番は勝手にリセットされず維持されているか？
- [ ] まとめ文書は**原則 1 本（最大 2 本）**に集約されているか？
- [ ] まとめ文書に**対象期間（例: `対象期間: YYYY-MM-DD 〜 YYYY-MM-DD`）**が明記されているか？
- [ ] まとめ完了後、不要となった元ファイルは整理・削除されているか？
- [ ] 全ドキュメントの作成・更新日時が JST 表記になっているか？
- [ ] Markdown内リンクがすべて相対パスで記載されているか？
