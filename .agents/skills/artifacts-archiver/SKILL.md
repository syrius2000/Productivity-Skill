# Artifacts Archiver (ドキュメント自動アーカイブ・整理スキル)

`./docs/Artifacts/` 内の実装計画書や報告書を整理し、復元可能性を保って `./docs/Archives/` へ統合・退避するスキル。実行フェーズへ進むのは、ユーザーが「アーカイブ」「古い計画の整理」「文書統合」などを明示した場合だけである。

## 概要

過去の計画・実装報告・検証報告を精査し、対象期間を明記したまとめ文書として `./docs/Archives/` へ退避します。文書数や進行フェーズの変化だけを理由に、候補選定・作成・移動・削除を始めません。
アクティブな計画書のファイル名や番号（例: `003`）は勝手に書き換えず保持し、トレーサビリティとリンクの健全性を維持します。

---

## 適用タイミング（Triggers）

- ユーザーが「過去の計画書をアーカイブして」「Artifactsを整理して」「古い書類をまとめて」「全部アーカイブして」などと指示した場合
- 「文書が増えた」だけでは起動しない。明示依頼がない場合は、読み取り調査や整理提案を自動で始めない

---

## ワークフローと手順（Workflow Steps）

### 1. 読み取り調査と対象一覧 (Inventory)

まず読み取り専用で `./docs/Artifacts/` と `./docs/Archives/` を調べ、対象候補を一覧にする。次の7列を固定する。

| パス | 状態 | 候補/除外 | 根拠 | リンク確認 | 復元情報 | 必要な承認 |
|---|---|---|---|---|---|---|

- **通常指示（「整理して」「アーカイブして」等）**では、完了根拠を確認できる過去計画・報告書だけを候補にする。進行中、未承認、完了不明、ユーザーが編集中、または他文書から参照中のファイルは候補から除外する。
- **全件指示（「全部アーカイブして」等）**でも、対象一覧を省略しない。「全消去整理」という語だけでは削除を開始しない。
- `./docs/Artifacts/` に残るアクティブな計画書の番号は、リセットや再採番を行わず維持する。

完了条件：候補と除外理由が、ユーザーが確認できるファイル一覧になっている。

### 2. 変更計画と明示承認 (Approval)

対象一覧を基に、作成するまとめ文書、移動または削除する元ファイル、修復するリンク、復元方法を提示する。同じ案件・目的の完了文書は、一緒に読むことで経緯と結論を理解できるなら、計画・実装報告・検証報告を一つのサマリーへまとめる案を最初に作る。段階ごとの日付や文書別の復元先が異なっても、対象期間と対応表に残せる限り分割しない。不明な復元先は移動・削除対象から保留する。目的・読者・アクセス制約が異なる、または一つにすると判断が混ざる具体的な理由がある場合だけ分け、その理由を候補一覧に書く。ファイルの作成、移動、削除、リンク書換えは、対象一覧を含む計画に対するユーザーの明示承認を得るまで実行しない。

完了条件：承認済みの対象一覧と変更範囲が固定されている。

### 3. 集約と検証 (Consolidation)

承認後にだけ、対象文書を精査し、承認済みのまとまりごとにまとめ文書を `./docs/Archives/` に作成する。本文は「対象と結論」「確定した決定と理由」「主要成果と検証の限界」「未解決事項と引継ぎ」「元文書と復元情報」の5節を基本とする。同じ事実は一度だけ記載し、古い判断が更新された場合は最終判断と更新理由を残す。重要な決定と未解決事項は、元文書から集約先の節への対応表で確認する。

元ファイルを削除または移動する前に、まとめ文書とMarkdown相対リンクを検証する。Git管理下では削除前後の `git diff --name-status` を確認し、想定外のファイルを変更しない。

完了条件：まとめ文書、リンク検証結果、変更対象が承認済み一覧と一致する。

### 4. 反映と復元情報 (Finalize)

検証が成功した後にだけ、承認済みの元ファイルを移動または削除する。削除したパス、復元元（Gitコミットまたは退避先）、未変更のアクティブ文書を報告する。復元不能な削除や、広いパスを対象にした再帰削除は行わない。

完了条件：反映後のファイル一覧と復元情報を報告できる。

## チェックリスト

- [ ] アーカイブ対象の選定はユーザー指示（通常 vs 全件）に合致しているか？
- [ ] アクティブな計画書のファイル名・連番は勝手にリセットされず維持されているか？
- [ ] 候補一覧は「パス」「状態」「候補/除外」「根拠」「リンク確認」「復元情報」「必要な承認」を含むか？
- [ ] 同じ案件・目的の完了文書を一つにまとめ、日付・復元先を対応表に残したか？
- [ ] 分けた文書には、目的・読者・アクセス制約・判断混在のいずれかの具体的な理由があるか？
- [ ] まとめ文書に**対象期間（例: `対象期間: YYYY-MM-DD 〜 YYYY-MM-DD`）**が明記されているか？
- [ ] まとめ完了後、不要となった元ファイルは整理・削除されているか？
- [ ] 全ドキュメントの作成・更新日時が JST 表記になっているか？
- [ ] Markdown内リンクがすべて相対パスで記載されているか？
