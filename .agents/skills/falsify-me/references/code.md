# コード：契約から反例と最小修正へ

期待する入力・出力、状態、副作用、例外、互換性を契約として固定する。契約が不明で判定を変えるときは確認する。入力範囲、状態遷移、並行実行、境界、外部依存から重要なものを選ぶ。

根拠にファイル・行、最小入力、期待結果、実際の結果または導出を示す。既存のガード、呼出側の保証、契約範囲を確認し、成立しない批判を捨てる。読むだけで導出できる失敗はDerived、実行で確認した結果はObserved、追加仮定が必要ならHypothesis。静的推論と実行再現を混ぜない。

例：空入力をValueErrorにする契約で `sum(xs)/len(xs)` のみなら、空リストでZeroDivisionErrorとなることをDerivedとして示せる。空入力のガードを提案し、空入力、単一値、通常値の確認を添える。ガードが既にあれば空入力の批判を撤回する。

必要なら契約と互換性を保つ最小差分を提示し、再検討で新たな副作用を探す。ファイル変更や実行はユーザーの許可範囲に従い、案を示しただけで修正済み・試験成功としない。

出力は、契約、重要な問題と証拠、最小反例、必要なら最小修正案、回帰確認と検証状態を中心にする。利用者・データ・業務への影響を追い、重要なら [リスクの詳細](risk-management.md) を読む。医薬品品質に影響する場合は患者保護と該当SOP・判断者を確認する。

重要な改善案では、可能なら採用前に、その案の効果や前提を覆す観測・反例を具体的に示す。実際に調べた範囲と未確認を区別し、些細な変更には形式的に要求しない。
