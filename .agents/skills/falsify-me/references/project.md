# PJ初期：破綻条件から成立する計画へ

目的、成功条件、対象範囲、不可欠な前提、外部依存、取り消しやすさを把握する。コード断片があっても、主目的が成立可能性ならこのモードを中心にする。

「何が、どの条件で失敗し、どの目的が達成できなくなるか」を因果で記述する。未知の前提は未知とし、未確認のサービス仕様を事実にしない。可能性を列挙するだけで終わらず、元案が既存の制約・管理策で耐えるか再検討する。

各重要事項へ、最小実験、観測する結果、継続・修正・中止の判断条件を付ける。根拠のない数値目標は作らない。前提検証、範囲縮小、手順変更、方式変更から必要な最小の修正を選ぶ。目的自体が達成不能なら方向転換や中止も示し、要件追加で無理に延命しない。

例：オフラインが必須なのに外部APIだけで判定する案は、オフライン時に判定できず成立条件を満たさない。元案FAILSと、ローカル処理を使う改善案の未検証状態は別に示す。通信を止めた環境で期待する入力・結果を観測する実験を提案する。

出力は、目的と成立条件、最重要の破綻シナリオ、最小実験、改善方針、判断条件を中心にする。影響、既存管理策、対策後の新規・残余リスク、判断者、必要な共有先、再評価する変更をつなぐ。重要な判断では [リスクの詳細](risk-management.md) を読む。リスク受容や着手承認を代行しない。
